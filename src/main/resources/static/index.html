Transactional Outbox Pattern

E-ticaret sipariş örneği · Sipariş Servisi → Outbox → Relay → Kafka → Fatura Servisi H2 Console · JDBC URL: jdbc:h2:mem:orderdb
OUTBOX

1. Sipariş oluştur

Sipariş + outbox kaydı tek transaction'da yazılır. Relay birkaç ms içinde Kafka'ya taşır, Fatura Servisi faturayı keser.

OUTBOX

2. Commit öncesi hata

Sipariş kaydedildikten sonra hata fırlar: sipariş de outbox kaydı da birlikte geri alınır. Kafka'ya hiçbir şey gitmez.

NAIVE / DUAL WRITE

3. Hayalet event

Event doğrudan Kafka'ya gönderilir, sonra DB rollback olur. Fatura Servisi var olmayan bir sipariş için fatura keser.

RELAY

4. Relay'i durdur

Siparişler alınmaya devam eder; event'ler outbox'ta PENDING olarak birikir. Devam ettirince sırayla gönderilir.

BROKER

5. Kafka erişilemez

Outbox ile sipariş yine alınır, relay retry yapar (5 denemeden sonra FAILED). Naive yöntemde ise sipariş alınamaz (503).

AT-LEAST-ONCE

6. Relay gönderip çöksün

Kafka ack verir ama processed_at yazılmadan relay çöker → event tekrar gönderilir. Inbox duplicate'i yakalar, tek fatura kalır.
